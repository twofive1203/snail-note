# 接入已有 Markdown 文件夹

Snail Note 不执行导入、复制或格式转换。添加笔记本只是保存服务端目录与笔记本之间的关联。

## 本地运行

1. 启动应用，无需配置 `NOTEBOOK_ROOT`。
2. 打开 Snail Note，点击左侧“笔记本”旁的 `＋`。
3. 在服务端目录浏览器中逐级进入目标文件夹。
4. 点击“选择当前目录”。

可以重复以上步骤添加多个目录。每个目录会作为独立笔记本显示；点击笔记本后可浏览其 Markdown 文件和子目录。笔记本列表默认保存在项目根目录的 `.snail-note/notebooks.json`，可通过 `SNAIL_NOTE_DATA_DIR` 修改存储位置。

从列表中移除笔记本只会删除这条关联，不会删除真实目录或文件。

## 旧配置兼容

如果升级前配置了 `NOTEBOOK_ROOT`，且新的笔记本配置文件尚不存在，服务首次启动时会把该目录注册为第一个笔记本。之后可以在界面中继续添加或移除笔记本。

## Docker Compose

在根目录 `.env` 中配置包含一个或多个笔记本的宿主机父目录：

```dotenv
NOTEBOOK_HOST_PATH=D:/Notes
```

然后启动：

```bash
docker compose up -d --build
```

Compose 会将该目录挂载到容器内的 `/notes`。打开页面后，可选择 `/notes` 本身或其不同子目录作为多个笔记本。

浏览器看到的是容器文件系统，而不是宿主机的完整文件系统。其他宿主机目录必须先通过 `volumes` 显式挂载到容器中。笔记本列表保存在 `snail-note-data` 数据卷中。

## 文件规则与风险

- 当前项目不含登录认证，目录浏览和笔记 API 只应暴露在可信本机或内网。
- 文件树和搜索仅处理 `.md` 文件；其他附件不会显示。
- 符号链接不会被扫描，以避免越过笔记本根目录。
- 保存会直接覆盖原文件；重命名、移动和删除也直接作用于真实文件。
- 非空目录不会被删除，目标已存在时不会覆盖。
